# Host ON (AI) — 핵심 화면 와이어프레임

> **설계 원칙과 라우트 목록은 `docs/ui_design.md`(SSOT)이고, 이 문서는 그
> 기준에 따른 화면 레이아웃이다.** `ui_design.md` 0절이 "와이어프레임(R35)은
> 이 문서에 포함하지 않는다"고 명시하고 있어 별도 파일로 둔다.

- **9/7 확정.** 체크리스트 R35(핵심 화면 와이어프레임 제작)의 산출물이다.
- `ui_design.md` 1-2절 **원칙 5(저해상도)**를 따른다 — 픽셀 위치·색상·폰트·
  아이콘 종류는 쓰지 않는다. **어느 영역에 무엇이 오는지만** 표시한다.

### (2) 영역별 구성 요소

- **헤더**: 로고 / `PropertySwitcher` 드롭다운 / 계정 메뉴
  - `PropertySwitcher` 드롭다운 **하단에 `+ 새 숙소 등록`** (→ `/onboarding`)
- **사이드바**: **운영 화면 8개** 평면 배치(계층·그룹 없음 — 원칙 3).
  (9/8 `/compliance`가 `/settings` 4번째 탭으로 흡수되어 9개 → 8개)
  `/login`·`/signup`·`/onboarding`은 AppLayout 밖이라 나타나지 않는다
  — 라우트 11개 ≠ 사이드바 메뉴 11개(`ui_design.md` 5-2절)
- **본문 상단**: 합산 KPI — 전체 숙소 합계
- **본문 중단**: 숙소별 카드 — 숙소명 + 신호등 + 지표 요약
- **본문 하단**: 긴급 액션 프리뷰 상위 N건 + `전체 보기 →`
- **배너**: 지식베이스 0건일 때만 노출

### (3) 데이터 출처

| 화면 요소 | API | 응답 필드 |
|---|---|---|
| PropertySwitcher 목록 | `GET /properties` | `property_id`, `name`, `accommodation_type`, `bookable_unit_type` |
| 병렬 호출 대상 | `GET /properties` | `property_id` |
| 합산 KPI | `GET /properties/{id}/dashboard/summary` × N | `today_checkin_count`, `today_checkout_count`, `today_turnover_count`, `conflict_count` |
| 숙소 카드 제목 | 〃 | `property_id`, `property_name` |
| 신호등 | 〃 | `red_now_count`, `yellow_today_count`, `green_auto_count` |
| 카드 지표 요약 | 〃 | `open_action_count`, `cleaning_pending_count`, `cleaning_issue_count` |

| 지식베이스 배너 조건 | `GET /properties/{id}/knowledge-chunks` | `[DB]` `chunk_id` (0건 여부 판정용) |

> **KPI는 서버가 합산하지 않는다.** `GET /properties`로 목록을 받은 뒤 각
> 숙소의 `dashboard/summary`를 **병렬 호출하고 프론트가 합산**한다
> (`api_contract` v2.0 4.2절). 교차 숙소 집계 엔드포인트는 만들지 않는다.

### (4) 상태별 변화

| 상태 | 레이아웃 변화 |
|---|---|
| LOADING | KPI 4칸과 숙소 카드 자리에 스켈레톤. 헤더·사이드바는 즉시 렌더 |
| EMPTY (숙소 0건) | 본문 3단을 모두 숨기고 중앙에 "첫 숙소를 등록해 주세요" + `/onboarding` 버튼 |
| EMPTY (액션 0건) | 하단 블록 자리에 "지금 처리할 일이 없습니다" — 정상 상태이므로 경고색 사용 금지 |
| ERROR (`GET /properties` 실패) | 본문 전체를 재시도 화면으로 대체 |
| **PARTIAL (부분 실패)** | 일부 숙소의 `dashboard/summary` 호출 실패. 아래 참고 |

**PARTIAL** — 병렬 호출 중 일부만 실패한 경우. 기존 4상태에 해당하지 않아
이 화면에만 두는 다섯 번째 상태다(`ui_design.md` 4-4절과 동일).

```
|  +--------+ +--------+ +--------+ +--------+                   |
|  | KPI    | | KPI    | | KPI    | | KPI    |  성공분만 합산     |
|  +--------+ +--------+ +--------+ +--------+                   |
|  3개 숙소 중 2개 기준          ← 집계 기준 표시                 |
|                                                                |
|  +----------------+ +----------------+                         |
|  | 숙소A  [신호등] | | 숙소B          |                         |
|  | 지표 요약      | | 불러오지 못함   |  ← 실패한 카드만        |
|  |                | | [다시 시도]    |                         |
|  +----------------+ +----------------+                         |
```

- 상단 KPI는 **성공한 숙소만 합산**하고 **몇 개 기준인지 표시**한다
- **실패한 숙소 카드만** 에러 + 재시도. 전체 화면을 에러로 처리하지 않는다
- 하단 액션 프리뷰는 성공한 숙소 기준으로 렌더링한다

### (4) 상태별 변화

| 상태 | 레이아웃 변화 |
|---|---|
| LOADING | 상세 모드는 본문 자리에 스켈레톤. 저장 시 `[저장]` 버튼만 스피너 + 폼 비활성 |

## 3. AI 인박스

공통 골격 동일. 본문은 **목록 + 상세 2단**.

### (1) 레이아웃

```
+------------------+---------------------------------------------+
|  문의 목록        |  문의 상세                                   |
|                  |                                             |
| +--------------+ |  게스트 원문                                 |
| | 문의 1  [뱃지]| |  +---------------------------------------+  |
| +--------------+ |  |                                       |  |
| | 문의 2       | |  +---------------------------------------+  |
| +--------------+ |                                             |
| | 문의 3       | |  [분류]  [우선순위]  [감지 언어]            |
| +--------------+ |                                             |
|                  |  AI 답변 초안                                |
|  (페이지네이션)   |  +---------------------------------------+  |
|                  |  |                                       |  |
|                  |  +---------------------------------------+  |
|                  |                                             |
|                  |  근거(RAG 출처)                              |
|                  |  - chunk 참조 목록                           |
|                  |                                             |
|                  |  재생성 잔여: N회                            |
|                  |          [재생성]  [거절]  [승인 후 발송]    |
+------------------+---------------------------------------------+
```

### (2) 영역별 구성 요소

- **좌측 목록**: 문의 행 + 상태 뱃지 / 페이지네이션(`?page=&size=`)
- **우측 상세**
  - 게스트 원문
  - **분류 / 우선순위 / 감지 언어**
  - **AI 답변 초안**
  - **근거(RAG 출처)** — 어느 지식에서 나왔는지
  - **재생성 잔여 횟수**
  - 버튼 3종: 재생성 / 거절 / 승인 후 발송

### (3) 데이터 출처

| 화면 요소 | API | 응답 필드 |
|---|---|---|
| 문의 목록 | `GET /properties/{id}/inquiries` | `[DB]` `inquiry_id`, `message`, `channel`, `created_at` |
| 게스트 원문 | `GET /inquiries/{id}` | `[DB]` `message`, `language` |
| 분류 | 〃 | `classification.category` |
| 우선순위 | 〃 | `classification.risk_level` |
| 자동응답 가능 여부 | 〃 | `classification.auto_respondable` |
| AI 답변 초안 | 〃 | `response.response_text` |
| 감지 언어 | 〃 | `response.detected_language` |
| 근거(RAG 출처) | 〃 | `response.sources` |
| 최신 응답 여부 | 〃 | `response.is_latest` |
| 자동 발송 여부 | 〃 | `auto_sent` |
| 재생성 | `POST /inquiries/{id}/regenerate` | — |
| 승인 후 발송 | `POST /inquiry-approvals/{approval_id}/approve` | — |
| 거절 | `POST /inquiry-approvals/{approval_id}/reject` | — |

> 위 `classification`·`response`·`auto_sent`는 `api_contract` 7절의
> **`POST /inquiries` 응답 예시**에 정의된 구조다. `GET /inquiries/{id}`는
> "분류+최신응답 포함"으로만 기술돼 있어 같은 구조를 전제한다.
>
> **재생성 잔여 횟수**는 응답 필드가 아니다. 7절 계산식
> (`retry_count = INQUIRY_RESPONSES 레코드수 - 1`, 상한 2)에 따라 **프론트가
> 표시용으로 계산**하거나 서버가 내려주도록 구현 시 정한다 — 현재 문서에
> 해당 필드가 없다.

### (4) 상태별 변화

| 상태 | 레이아웃 변화 |
|---|---|
| LOADING | 목록은 스켈레톤. 재생성 중에는 **AI 답변 초안 영역만** 스피너, 원문·분류는 유지 |
| EMPTY | 2단을 합쳐 "받은 문의가 없습니다". 지식베이스 0건이면 `/knowledge` 등록 유도 함께 표시 |
| ERROR (429 `MAX_RETRY_EXCEEDED`) | `[재생성]` 버튼 **비활성** + 잔여 0 표시 → **호스트 수동 작성 모달**로 전환. 모달은 AI 초안을 초기값으로 넣고 직접 편집 |
| ERROR (기타) | 상세 영역 상단에 인라인 에러. 목록은 유지 |

```
|  | ID | 체크인   | 체크아웃 | 총액   | 수수료 | 실수령 | 상태|  |
|  +----+----------+----------+--------+--------+--------+-----+  |
|  |    |          |          |        |        |        |     |  |
|  +----+----------+----------+--------+--------+--------+-----+  |
+----------------------------------------------------------------+
```

### (2) 영역별 구성 요소

- **월 선택** + `일괄 확정` 버튼
- **월별 스냅샷**: 총 예약 수 / 총 매출 / 수수료 / 실수령 / 적용 수수료율
- **수수료 설정**: **접힌 섹션**(평소 접혀 있음). 펼치면 수수료율 등 편집
- **예약별 내역 표**: 예약 단위 금액과 정산 상태

> **`net_amount`와 `net_payout`은 서로 다른 컬럼이다.**
> `net_amount`는 **예약 1건**의 실수령액(`RESERVATIONS`),
> `net_payout`은 **월 단위 집계**의 실수령액(`MONTHLY_SETTLEMENTS`)이다.
> 표에서 섞어 쓰지 않는다(`api_contract` 4절 v1.6 정정 사항).

### (3) 데이터 출처

| 화면 요소 | API | 응답 필드 |
|---|---|---|
| 월별 스냅샷 — 총 예약 | `GET /properties/{id}/settlements` | `[DB]` `total_reservations` |
| 총 매출 | 〃 | `[DB]` `gross_revenue` |
| 수수료 | 〃 | `[DB]` `channel_fee` |
| 실수령(월) | 〃 | `[DB]` `net_payout` |
| 적용 수수료율(스냅샷) | 〃 | `[DB]` `applied_commission_rate` |
| 대상 월 | 〃 | `[DB]` `target_month` |
| 수수료 설정(접힌 섹션) | `GET·PATCH /properties/{id}/financial-config` | `[DB]` `commission_rate`, `fee_type`, `vat_included`, `base_nightly_rate` |
| 예약별 내역 | `GET /properties/{id}/reservations` | `reservation_id`, `check_in`, `check_out`, `gross_amount`, `fee_amount`, `net_amount`, `financial_status` |
| 일괄 확정 | `POST /properties/{id}/settlements/{month}/confirm` | — |

> **`GET /properties/{id}/settlements`와 `financial-config`의 응답 예시가
> `api_contract`에 없다.** 위 `[DB]` 필드는 DB명세서 v1.3의
> `MONTHLY_SETTLEMENTS`·`FINANCIAL_CONFIGS` 컬럼명이며, **응답 필드명은
> 정산 구현 시 확정**한다.

### (4) 상태별 변화

| 상태 | 레이아웃 변화 |
|---|---|
| LOADING | 스냅샷 카드와 표 자리에 스켈레톤. 월 선택은 즉시 조작 가능 |
| EMPTY | 스냅샷 카드를 0으로 표시하지 않고 표 자리에 "정산할 예약이 없습니다". 해당 월에 체크아웃 예약이 없다는 맥락을 함께 안내 |
| ERROR | 확정 실패 시 상단에 인라인 에러 + 표는 그대로 유지(부분 반영 없음 — 단일 트랜잭션) |

> 금액이 추정치인지 확정인지 `financial_status`(`ESTIMATED` /
> `CONFIRMED` / `MANUALLY_ADJUSTED`)로 **반드시 구분 표시**한다.

## 5. 온보딩

**단일 URL, 2스텝.** 헤더·사이드바 **없음**(가입 직후 경로).

### (1) 레이아웃

**STEP 1 — 숙소 등록 + 판매단위**

```
+----------------------------------------------------------------+
|  [====== STEP 1 ======]------- STEP 2 -------                  |  프로그레스
+----------------------------------------------------------------+
|  숙소 이름     [__________________]                             |
|  숙박업 유형   [________________ v]   (6종)                     |
|  주소          [__________________]                             |
|  기본 요금     [__________]                                     |
|  체크인/아웃   [____] / [____]                                  |
|                                                                |
|  판매 단위     ( ) PROPERTY  ( ) ROOM  ( ) BED                  |
|                                                                |
|  --- ROOM / BED 선택 시에만 아래가 펼쳐짐 ---                   |
|  +----------------------------------------+                    |
|  |  객실 [__________]        [+ 객실 추가] |                    |
|  |    └ BED 선택 시: 침대 [____] [+ 추가]  |                    |
|  +----------------------------------------+                    |
|  ------------------------------------------                    |
|                                                                |
|                                        [다음 →]                |
+----------------------------------------------------------------+
```

**STEP 2 — iCal 연동**

```
+----------------------------------------------------------------+
|  ------- STEP 1 -------[====== STEP 2 ======]                  |
+----------------------------------------------------------------+
|  채널     [____________ v]                                      |
|  iCal URL [__________________________]   [+ 채널 추가]          |
|                                                                |
|  등록된 채널 목록                                               |
|  +--------------------------------------------+                |
|  |                                            |                |
|  +--------------------------------------------+                |
|                                                                |
|  [나중에 하기]                          [완료 →]               |
+----------------------------------------------------------------+
```

### (2) 영역별 구성 요소

- **상단 프로그레스바**(2단계) — 현재 스텝 표시
- **STEP 1**: 숙소 기본 정보 + 판매 단위 선택 + **조건부 객실/침대 폼**
  - `PROPERTY` 선택 시 객실 영역은 **펼쳐지지 않는다**
  - `ROOM` 선택 시 객실 입력, `BED` 선택 시 객실 아래 침대 입력까지
- **STEP 2**: 채널 + iCal URL + 등록 목록
  - **`[나중에 하기]`는 좌측 하단**, `[완료 →]`는 우측 하단에 둔다
- **완료 후 `/dashboard`로 진입**

### (3) 데이터 출처

| 화면 요소 | API | 요청/응답 필드 |
|---|---|---|
| 숙소 등록 | `POST /properties` | (요청) `name`, `accommodation_type`, `bookable_unit_type`, `address`, `base_price`, `checkin_time`, `checkout_time`, `weekday_adjustment_enabled`, `holiday_adjustment_enabled` |
| 숙박업 유형 6종 | 〃 | `URBAN_HOMESTAY`, `RURAL_HOMESTAY`, `HANOK`, `HOSTEL`, `LODGING_FACILITY`, `GENERAL_LODGING` |
| 객실 등록 | `POST /properties/{id}/rooms` | `[DB]` `room_name` |
| 침대 등록 | `POST /rooms/{room_id}/beds` | `[DB]` `bed_label` |
| 채널 등록 | `POST /properties/{id}/channels` | `[DB]` `channel`, `external_property_id` |
| 등록된 채널 목록 | `GET /properties/{id}/channels` | `[DB]` `connection_id`, `channel`, `sync_status`, `last_synced_at` |

### (4) 상태별 변화

| 상태 | 레이아웃 변화 |
|---|---|
| LOADING | `[다음 →]` / `[완료 →]` 버튼만 스피너 + 폼 비활성. 프로그레스바는 유지 |
| EMPTY | 해당 없음(입력 전용 화면) |
| ERROR (STEP 1) | 필드별 인라인 에러. `accommodation_type` 허용값 위반은 해당 필드 하단 |
| ERROR (STEP 2) | **STEP 2에 머문 채** 재시도 안내. 숙소는 이미 등록됐으므로 STEP 1로 되돌리지 않는다. `[나중에 하기]`로 건너뛸 수 있음 |
